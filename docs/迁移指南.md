# 环境迁移指南

以 water plant 为例，其他环境按以下要点迁移。

1. **调整 XML 和资产布局**
   - 公共资源放在 `src/dexjoco/assets/common/`。
   - 机器人模型放在 `src/dexjoco/assets/robots/`。
   - 任务场景和物体放在 `src/dexjoco/assets/tasks/<task>/`。
   - `include` 路径相对当前 XML；mesh、texture 路径统一相对 `assets/` 根目录。

2. **关闭抗锯齿**
   - 场景 XML 设置 `<quality offsamples="0" />`，用于保证重复回放的图像一致性。

3. **compiler 只在顶层配置**
   - 只在场景入口 XML 设置 `compiler`，被 include 的 XML 不再配置。

4. **initial state 单独保存**
   - `state` 只包含机器人观测，不混入物体初始位姿、桌高等恢复信息。
   - 初始场景通过 `reset(options={"initial_state": ...})` 恢复，并通过 `info["initial_state"]` 返回。
   - 数据集将恢复信息单独存入 `replay_initial_values.jsonl`。

5. **成功、失败逻辑提取为状态机**

6. **渲染资源延迟创建**
   - 构造函数不创建 renderer 或 GUI，首次需要时再创建。

7. **使用 uv 安装**
   - 在根目录 `pyproject.toml` 声明依赖，执行 `uv sync` 安装。
   - 命令统一通过 `uv run` 运行。

8. **支持 EnvHub 加载**
   - 在 `src/dexjoco/envhub.py` 注册任务，通过根目录 `env.py` 暴露 `make_env`。
   - 新任务同步接入配置、回放和测试的任务选择，避免仍固定加载 water plant。

9. **测试回放一致性**
   - 使用`uv run pytest`测试回放是否成功，回放图像是否一致

其他细节可以对比main分支和feat/lerobot分支的差异
